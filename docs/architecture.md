# 系统架构与开发边界

## 1. 总体结构

```text
Qt 用户端 ── TCP/JSON ── Qt 管理服务端 ── SQLite
                              │
                              ├── 统计接口 ── ECharts 大屏
                              └── 特征数据 ── 负荷预测模块
```

桌面端只负责交互与展示；订单状态、钱包扣款、电桩占用等关键规则统一放在服务端，避免两个客户端各自维护一套业务逻辑。

## 2. 模块职责

- 用户端：手机号登录、个人资料、附近电站、导航、预约、充电、订单结算。
- 管理端：管理员认证、营收、电桩状态、电站管理、电桩管理、用户冻结/解冻。
- 核心库：数据模型、数据库连接、协议编解码、通用错误类型。
- Web 大屏：只读运营指标展示，不直接连接 SQLite。
- 智能分析：接收脱敏后的历史特征，输出 1/6/24 小时负荷预测。

## 3. Socket 协议

初期采用“每行一条 JSON”的 TCP 协议，便于调试：

```json
{"id":"request-uuid","type":"station.list","payload":{"latitude":39.9,"longitude":116.4}}
```

响应沿用相同 `id`，`type` 使用 `<请求类型>.ok` 或 `<请求类型>.error`。所有写操作必须由服务端再次校验身份和数据状态。

## 4. 并发原则

- GUI 线程不得执行长查询、网络等待或模型推理。
- 每个 TCP 连接可交给线程池处理；数据库连接必须按线程创建，不能跨线程共享 `QSqlDatabase`。
- 订单创建、结束充电、扣款必须使用数据库事务。
- 利用数据库唯一索引保证每位用户最多存在一个未完成订单。

## 5. 配置与安全

- 腾讯地图 Key、监听地址等敏感配置从环境变量或未纳入版本控制的本地配置读取。
- 管理员密码必须使用 Argon2、scrypt 或 bcrypt 等密码哈希；`admin/123456` 仅用于首次本地演示。
- Socket 正式部署前应增加 TLS、登录令牌、请求大小限制、超时和速率限制。
- SQL 全部使用绑定参数，禁止拼接用户输入。

## 6. 里程碑

1. 数据库与仓储层。
2. 用户/管理员认证与 TCP 通信。
3. 电站、电桩、订单、钱包业务闭环。
4. 图表、大屏与地图。
5. 异常处理、自动化测试和演示数据。
6. 负荷预测与推荐优化。

## 1. 环境准备

### 1.1 构建

```bash
cd ~/EV-Charging-Platform
cmake --preset dev          # 首次或 CMakeLists 变更后
cmake --build build/dev -j4
```

产物:`build/dev/apps/admin-server/charging-admin`、`build/dev/apps/user-client/charging-user`。

也可用 Qt Creator 打开根目录 `CMakeLists.txt`,选 Desktop Qt 6.4.2 套件构建。

### 1.2 启动顺序与端口

| 程序 | 启动命令 | 端口 |
|---|---|---|
| 管理端+TCP 服务 | `./build/dev/apps/admin-server/charging-admin` | 45454(监听所有网卡) |
| 用户端 | `./build/dev/apps/user-client/charging-user` | —(连接 127.0.0.1:45454) |
| Web 大屏 | `python3 web/dashboard/server.py`(在 web/dashboard 下) | 8080 |
| 预测服务(可选) | `python3 ml/service.py ...` 或 `python3 /tmp/mock_ml.py` | 8090 |

**必须先启动管理端**(SQLite 数据库随它初始化),再启动用户端。
用户端可用环境变量指定服务地址:`CHARGING_SERVER_HOST` / `CHARGING_SERVER_PORT`。

### 1.3 本机 QML 运行时模块(仅 192.168.202.128 这台虚拟机需要)

启动图形界面前,任选其一:

```bash
# 方案 A:一次性安装(需 sudo 密码)
sudo apt install qml6-module-qtquick-templates qml6-module-qtquick-window qml6-module-qtwebengine
# 方案 B:使用已解包目录
export QML_IMPORT_PATH=/home/bit/qt-extra-qml/usr/lib/x86_64-linux-gnu/qt6/qml
```

方案 B 时从**同一个终端**启动程序(子进程继承环境变量);Qt Creator 需在
Projects → Run → Environment 里给两个运行配置各加一次该变量。

### 1.4 演示账号与数据重置

- 管理员:`admin / 123456`(首次登录会强制改密,见 3.1)
- 用户端:任意 11 位手机号自动注册(如 `13800138000`),无需密码
- **数据重置**:停止管理端 → 删除项目根目录 `charging_platform.db` → 重启管理端,
  会自动重建 schema + 演示数据(管理员密码回到 123456,全部订单/预约清空)

## 5. 异常与边界汇总

| 场景 | 操作 | 预期 |
|---|---|---|
| 服务未启动 | 直接启动用户端 | 界面提示未连接,自动重连;不崩溃 |
| 余额不足 | 结算金额大于余额 | 拒绝结算并提示;订单保持待结算;余额不变 |
| 并发预约 | 两个用户同抢一桩 | 只有一个成功 |
| 超大消息 | (高级)向 45454 发送 >1MiB 单行数据 | 服务端返回 protocol error,连接不中断 |
| 非法 JSON | 发送乱码行 | 返回 `protocol.error`,后续请求仍正常 |
| 图片损坏 | 选一个扩展名是 png 但内容非图片的文件 | 提示"无法解析图片文件" |

## 6. 建议的演示/验收路径(10 分钟)

1. 管理端首登改密(A1–A4) → 总览看指标与 7/30 切换(A7–A9)。
2. 用户端登录 → 浏览电站 → 预约 → 开始充电 → 停止 → 充值 → 结算(U8–U15)。
3. 管理端订单页看到该订单(A17);Web 大屏营收刷新(W2)。
4. 用户端带活动订单重登,展示强制引导弹窗(U18–U19)。
5. 启动 mock 预测服务,展示预测页真实数据(A21)。
6. 冻结用户演示权限控制(A18–A19)。
